# 08 中间的图：改成 Obsidian 式的力导向知识图谱

日期：2026-10-04

## 为什么改

中间的图是用户交互的主要入口，但原来的实现是一张静态 SVG：

- 只有选中的疾病和最近的 10 个邻居，切片里的基因、机制、患者组织、研究、研究者都不在图上。
- 节点位置固定在一个圆上，不能拖动，也不能缩放。
- 点邻居节点会直接把它换到中心并滚回页面顶部，看起来像没反应；中心节点点了没有任何效果。

第一版改用 Cytoscape 画固定构图（自己的社区在一侧、邻居排成弧），能点能拖，但看起来像一张排好的示意图。用户希望像 Obsidian 的关系图那样，于是换成实时力导向布局。

## 决定

| 问题 | 选择 |
|---|---|
| 用什么画 | force-graph 1.52.0（基于 d3-force，canvas 绘制）。文件放在 `views/src/vendor/`，开头保留 MIT 许可声明，由 `build_view.py` 嵌进页面，页面仍然是单文件、离线能打开 |
| 布局 | 持续运行的力导向模拟：节点互相排斥，连线像弹簧，一个向中心的引力。选中的疾病固定在中心；拖动它会停在放下的位置 |
| 点击 | 单击看详情和来源，双击疾病才把它换到中心 |
| 颜色 | 按 dataviz 规范：全部节点同时出现的图里超过 3 个色相就难以区分，所以只有疾病用颜色（机制聚类，与左栏一致），基因用墨色；机制、通路、症状画成空心圆，患者组织、研究、人、论文、资助都是灰点，靠标签、图例和悬停区分 |
| 切片外的疾病 | 照样显示基因、机制、共享通路、邻居；只和切片有关的图层按钮变灰 |

## 图上有什么

选中的疾病、它和邻居的致病基因、机制（切片内用 per gene-disease 的判断，切片外用 Orphanet 的功能方向）、共享通路、可选的共享症状；切片内再加上每个基因的患者组织、研究（中心疾病的基因最多各 8 个，邻居的基因各 2 个和 1 个）和"共同的人"：通过不同论文、资助或研究同时连着中心疾病的基因和另一个基因的研究者、组织、研究（与旅程区"网络重叠"卡片规则一致，排除资助机构）。

| 编码 | 含义 |
|---|---|
| 节点大小 | 连接数越多越大 |
| 疾病外圈颜色 | 线索判定（supported / plausible / weak / same gene / counterexample） |
| 灰点带外圈 | 连着两个基因的人、组织或研究 |
| 虚线 | inferred（相似度、ClinVar 变异谱推断）；实线是 observed |
| 邻居之间的淡虚线 | 两个邻居彼此也相似，力很弱，只用来让相近的疾病靠拢 |

## 交互

| 操作 | 结果 |
|---|---|
| 悬停节点 | 它和直接相连的节点、连线亮起并显示名字，其余淡出（约 0.2 秒渐变） |
| 悬停连线 | 提示框显示这条关系和证据类型 |
| 单击节点 | 侧栏显示详情；高亮保持到点空白处 |
| 单击连线 | 切片内的线打开证据记录（来源、引用、置信度、矛盾），多条记录时列出全部；切片外的线显示数据库条目：基因-疾病链接到 OMIM / Orphanet，基因-通路链接到 Reactome，共享症状链接到 HPO，相似度显示两项分数和共享内容 |
| 双击疾病 | 换到中心，右栏和旅程区一起更新 |
| 拖动节点 | 相连的节点被弹性地带着走，松手后整张图重新稳定 |
| 滚轮、双指 | 缩放；名字按缩放程度渐显：适配视野时只显示疾病、基因、机制，放大到 1.3 倍显示通路、组织和"共同的人"，再放大显示研究、研究者、论文、资助 |
| 图层按钮 | 显示或隐藏各类节点；数字是可显示的数量 |
| Fit / Reset / Forces | 适配视野 / 重新开始布局 / 调中心引力、排斥力、连线长度（记在浏览器里，下次打开沿用） |
| 在旅程区选一条线索 | 图上只亮这条证据链：疾病 ← 基因 → 共享通路 ← 基因 → 邻居疾病 |
| 悬停右栏的邻居列表 | 图上对应的疾病和它的连接亮起 |

## 数据

`build_view.py` 多嵌入一份"atlas links"，让切片外的每条线也有真实来源：

| 字段 | 内容 |
|---|---|
| `gp` | 基因符号 → 它参与的、出现在邻居共享通路里的 Reactome 通路 |
| `pu` | 每个通路的 Reactome ID（两个通路名各对应两个 ID，取第一个） |
| `tu` | 每个共享症状的 HPO ID |
| `gd` | 每种疾病的致病基因链接：基因、来源（OMIM / Orphanet）、编号、关联类型 |
| `date` | 图谱的检索日期 |

页面从 4.07 MB 增加到 4.99 MB：force-graph 0.17 MB，atlas links 约 0.74 MB。

## 改动的文件

| 文件 | 改动 |

## 检查

用无头 Chrome 通过 DevTools 协议驱动页面，控制台没有错误或警告：

1. STXBP1 种子疾病：默认 64 个节点、116 条线，约 4 秒稳定后自动适配视野。
2. 真实鼠标点击 STXBP1 基因：侧栏打开它的全部连线，图上 27 个节点保持高亮、37 个淡出。
3. 拖动 CASK 150 px：它的 8 个邻居跟着移动 7–90 个单位，松手后回弹。
4. 真实鼠标双击 DEE63：地址栏、右栏、图一起换到 DEE63。
5. 在旅程区选 STXBP1 ↔ CPLX1 线索：图上只亮 2 个疾病、2 个基因、3 个共享通路。
6. Forces 面板把连线长度调到 1.8：布局重新展开，设置写进浏览器存储。
7. Gaucher 病（切片外）：20 个节点，6 个切片图层按钮变灰；各类连线的来源都能打开。
8. 深色模式：颜色跟随系统切换。390 px 宽：画布跟随容器，页面没有横向滚动。

## 还没做的

- 布局每次从 d3-force 的默认初始排列开始，同一种疾病每次打开大体相同，但拖动过之后点 Reset 会重新展开。
- 手机上图偏小，需要双指放大。
- 滚轮在图上时会缩放而不是滚动页面，这是 Obsidian 的习惯，但在长页面里可能需要适应。
