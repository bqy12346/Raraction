# 02 设计思路

## 为什么先做一个切片，而不是全量扩展

PDF 写的 24 小时目标是"展示一条完整的旅程：从疾病到关联，再到共同行动"，评审标准里的 Patient progress 也是看能否走完这条路径。所以先在一个聚焦的切片上把每一层都补齐，比把 7,999 种疾病各补一点更有说服力。PDF 的 Data Sources 部分也建议先从一个有足够生物学、研究和患者组织信息的切片开始。

**选 STXBP1 的理由**

- PDF 的示例界面直接用了 STXBP1。
- 原有 README 已经验证过，它在图谱里的邻居是突触囊泡释放相关的基因（SYT1、VAMP2、CPLX1），疾病名称各不相同。这正是 PDF 说的"名称掩盖了机制"。
- 社区资源丰富：有患者组织、注册库、自然史研究，还有一个基因治疗试验，能演示"可复用的资产"。
- 切片里有天然的反例。GLS 一个基因对应几种病，一种是功能丧失，另一种（白内障、谷氨酸过量）是功能亢进，正好对应 PDF 第 4 页"同一基因、不同机制"的图。
- STXBP1 本身在数据库里没有机制方向，正好需要从论文里抽取，用来展示 OpenAI 的作用。

**切片范围**：种子疾病（MONDO:0012812），加上它在图谱里的 12 个邻居，再加上这些疾病的核心基因导致的所有疾病。核心基因不包括那些列了 3 个以上基因的"总称疾病"。结果是 12 个基因、42 种疾病。

## OpenAI 扮演什么角色

原则：**数据库能确定回答的，不交给模型。模型只做两件事：读非结构化文本，以及把图翻译成人能读懂的话。它的每个输出都必须能指回一条有来源的边。**

ID 对齐、邻居计算、机制判定、线索判定，都由确定性的代码完成。这样评委看到的每一条证据链都可以核查，模型说错了也能被发现。

| 角色 | 做什么 | 怎么防止模型出错 |
|---|---|---|
| Extract（价值最高） | 从 PubMed 摘要中抽取机制论断（功能丧失、功能获得、显性负效应）、证据类型、资产（动物模型、化合物、生物标志物） | 引用必须逐字出现在摘要里，否则丢弃；基因必须是这篇论文对应的切片基因 |
| Reconcile | 判断论断说的是哪一种病 | 只能从给定的疾病 ID 列表里选，列表外的 ID 一律清空 |
| Explain | 给每条线索写通俗解释、可复用的东西、差异、专家问题、本周下一步、提案草稿；没有路径时写"未知什么、下一步验证什么" | 每句话必须引用给定的边编号，引用了不存在的编号的句子会被删除 |

**运行方式**：构建时预先算好，结果缓存到 `data/slice/cache/openai/` 并提交。这样评委没有 Key 也能完整复现和演示。

**为什么不用 openai SDK**：原仓库的构建脚本只用 Python 标准库，所以这里直接调用 REST 接口（Chat Completions 的 structured outputs，严格 JSON schema），不额外增加依赖。

## 证据规则：三种证据类型

| 类型 | 含义 | 例子 |
|---|---|---|
| `observed` | 数据库、注册信息或组织官网明确写着的 | HPO 症状、ClinicalTrials.gov 的研究、患者组织网页上的句子 |
| `extracted` | 模型从论文摘要里读出来的 | "STXBP1 单倍剂量不足导致功能丧失"，附原文 |
| `inferred` | 图谱算出来的提议，需要人核实 | 邻居疾病相似度、按 ClinVar 变异谱推断的机制 |

## 判定规则（全部是确定性的代码）

### 机制：按"基因-疾病"判断，而不是按基因

同一个基因的不同疾病可能方向相反，按基因判断就会犯 PDF 警告的错误："把相同的基因名当作足够的证据"。

| 级别 | 来源 |
|---|---|
| 已确认 | 论文抽取的论断（指明了这个基因和这种病），或 Orphanet 在这条基因-疾病链接上标注的方向 |
| 仅提示 | ClinVar 变异谱：致病变异里截断型占比 ≥ 30% 提示功能丧失，否则标为"错义为主、方向未定" |
| 未知 | 以上都没有 |

基因层面的结论只能用到"这个基因只导致这一种具体疾病"的情况。总称疾病（列了很多基因）不给单一的机制标签。

### 线索：同时回答两个问题

对每个邻居疾病，分别回答：

1. **能否共享基础设施？** 看症状重叠程度（表型相似度 ≥ 0.12）。症状相近，注册库、结局指标、自然史数据就可能通用。这一点和机制是否一致无关。
2. **能否共享治疗策略？** 比较承载共享通路的那两个基因的机制。
   - 两边都已确认且方向相同：likely
   - 方向相同，但至少一边只是"仅提示"：possible
   - 方向相反：unlikely
   - 至少一边未知：unknown

判定结果：

| 判定 | 条件 |
|---|---|
| Supported lead | 机制相似度 ≥ 0.25、症状重叠、治疗策略 likely，并且已有共享的研究、组织或研究者，或者对方已经有患者组织或研究 |
| Plausible lead | 相似度够高、症状重叠，或者已有直接连接 |
| Counterexample | 机制方向相反（功能丧失 vs 功能获得，或 vs 显性负效应） |
| Same gene | 同一个基因 |
| Weak lead | 其余情况 |

显性负效应和功能丧失被视为"相反"，因为它们对应不同的治疗思路：基因补充对前者无效。

### 网络重叠（桥梁）

一个研究者、组织、资助方或研究，要通过**至少两个不同的项目**（论文、资助、研究）连接两个基因社区，才算桥梁。一篇同时提到两个基因的论文只算一个项目。

研究者按"姓 + 完整的名"跨来源匹配，还要求两条关联记录里的单位有相同的词。大型资助机构（如 NINDS）几乎资助所有方向，界面上不把它们列为桥梁。

### 缺口

对每种疾病，列出每个查过但没有结果的来源（患者组织、研究、资助、论文、资产、机制、邻居），让"没有结果"永远不会悄无声息。这对应 PDF 的"No supported route? Say so"。

## 数据源的匹配规则（防止误匹配）

- **基因符号的歧义**：纯字母的符号（GLS、CASK）容易和缩写撞车，必须同时出现基因全名，或者符号后面紧跟 variant / knockout / protein 之类的词。带数字的符号（STXBP1、SCN8A）出现即可。
- **临床试验**：基因符号要出现在疾病条件或关键词里，或者紧挨着 variant / related 之类的词；并且试验全文要提到遗传学、癫痫或基因全名。
- **患者组织**：先人工搜索得到候选清单（[data/slice/patient_orgs_seed.tsv](../../data/slice/patient_orgs_seed.tsv)），再由脚本抓取原网页，在同一句话里找到全部关键词才收录，并把那句话存为引用。验证不通过的直接丢弃。所以候选清单里放猜测也是安全的。
- **隐私**：临床试验的联系邮箱和电话不复制进图谱，界面只链接到 ClinicalTrials.gov 的官方页面。

## 界面思路

按 PDF "What Good Looks Like" 那段的顺序组织：

1. 你的疾病：机制标出确认级别，列出现有的社区
2. 谁和你有共同特征：邻居地图和线索列表，带判定
3. 为什么相连、能一起做什么：证据链、两边的机制、判定理由、可复用的东西
4. 下一步：本周可以做的事和提案草稿（模型生成的部分待运行）

旁边还有两块：网络重叠（谁已经连接了你的社区和别的社区）、缺口（我们不知道什么）。

任何证据都可以点开，查看来源、证据类型、置信度、原文引用和矛盾证据。网址锚点（`#d=...&lead=...&p=...`）记录当前位置，方便录演示视频时直接跳转。
